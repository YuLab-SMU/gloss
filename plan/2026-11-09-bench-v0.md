# Bench v0: sample, freeze, and first capture feedback

> Status: active.
> Date opened: 2026-11-09. Owner: Yonghe Xia.

**Goal:** A frozen, stratified benchmark of runnable R figures (code plus data), split into development and held-out sets, with attempted and retained counts and failure classes; and capture measured on the development set.

**Why now:** M0 Task 9 ([plan/2026-11-09-m0-substrate.md](2026-11-09-m0-substrate.md)) has to land before M1 tunes any rule (design §评测设计). It is also the first objective feedback on capture: M0 tested it on six hand-picked inputs only ([dev log](../dev_logs/2026-11-09-feedback-driven-workflow.md), *What's next*).

**Starting state (measured, 2026-11-09):**
- Suite: 7 files, 268 expectations, 0 failed, 0 skipped (`NOT_CRAN=true Rscript -e "devtools::test()"`).
- Capture on unpicked figures: never measured.
- Frame sizes, probed by hand (scripts to be committed in Task 1):
  - R Graph Gallery, commit `8be6801` (2026-10-22): 344 `.Rmd` posts, 2416 R chunks; 55 posts read data from a URL; the posts load 154 distinct packages, 85 of them not installed here.
  - ggplot2 extensions gallery (`ggplot2-exts/gallery`, `_config.yml`): 170 packages, 145 marked as on CRAN.
  - Bioconductor release VIEWS (2026-11-06): 2418 packages, 469 in the Visualization view, 459 of them with vignettes; 102 packages with vignettes import ComplexHeatmap. The local install is Bioconductor 3.21, so the frame uses the 3.21 VIEWS.
  - ComplexHeatmap: 253 help topics with examples; patchwork: 14.
  - TidyTuesday (`rfordatascience/tidytuesday`): each week holds data, a readme and images; **no figure code**.

**Assumptions to test (riskiest first):**
1. *Capture survives figures nobody picked.* Tested in Task 6. Predictions are committed before the run (Task 5). If most failures are capture errors rather than refusals, M1 waits for capture fixes.
2. *Enough sampled figures run from a frozen snapshot with the network off.* Tested in Task 4. If fewer than 100 of about 160 attempts are retained, add a second sampling round with the same rules and a new recorded seed, instead of hand-picking replacements.
3. *The figure produced by a chunk can be recovered as a capturable object* (a returned ggplot, patchwork, Heatmap or grob; else a base plot from the display list; else a grid scene through `grid.grab()`). Tested in Task 3 on a few PSUs, then in Task 4. If `grid.grab()` scenes fail capture often, report them as their own class.
4. *The design's four sources give an enumerable frame.* Already contradicted for TidyTuesday (see Scope changes).

**Architecture:** Everything lives under `bench/`, outside the package build (`.Rbuildignore`). Scripts in `bench/R/`; frame tables in `bench/frame/`; the sample in `bench/sample.csv`; one directory per retained figure in `bench/figures/<id>/` (`code.R`, `data/`, `meta.json`); attempts and runs in `bench/runs/`; the split in `bench/split.csv`; a checksum manifest at freeze. Each PSU (post, help topic, package vignette) runs in its own `callr` subprocess with a timeout, `set.seed()` fixed per figure, and a separate package library (`~/.cache/gloss-bench/lib`) so the user library is not touched. Source checkouts and downloads stay in `~/.cache/gloss-bench/src`, never in the repo tree. Not touched: the package code in `R/`, unless Task 6 finds a capture bug (then a separate fix commit with its own test).

**Sampling design (v0):**
- Unit: one figure drawn on an R graphics device by one chunk (Gallery), one example (help topic) or one vignette chunk (Bioconductor). htmlwidgets and tables are outside the population and counted as such.
- Two stages: first a PSU (post, package, topic) at random within its stratum; then one figure at random among the figures the PSU actually produces when run (for the engine strata, among figures of that engine).
- Strata and allocation (about 160 attempted): Gallery posts 70; ggplot2-exts CRAN packages 30; Bioconductor Visualization packages 30; patchwork 15 (Gallery posts loading patchwork plus patchwork help topics); ComplexHeatmap 15 (ComplexHeatmap help topics plus vignettes of Bioconductor packages importing it). Engine strata are oversampled on purpose; frame sizes and sample sizes per stratum are recorded so population figures can be weighted. A PSU drawn in an earlier stratum is not drawn again.
- Seed `20261109`, recorded in `bench/sample.csv` and `bench/README.md`.
- Chart type is recorded per figure (Gallery section; geoms after build for ggplot) but not stratified on: outside the Gallery there are no chart-type labels to stratify by before running.
- Missing packages are installed from CRAN or Bioconductor 3.21 into the bench library; an install failure is the failure class "missing package". URL data found in the code are downloaded into `data/` and the literal rewritten; the rewrite is recorded in `meta.json`.
- Eligibility runs with the network blocked (dead proxy); anything still reaching the network fails as "needs network".
- Split: 50/50 within each stratum, seeded, after eligibility and before any capture run.

**Out of scope:** classification and binding on the benchmark (M1); two-rater labelling rubric (M1, before held-out labelling); the perturbed and counterfactual sets (M5); the post-cutoff subset (needs a model choice); running capture on the held-out set (only once a plan reports numbers).

**Tech stack:** R 4.5.2, callr, jsonlite, tools (Rd), BiocManager 3.21, knitr (purl); git sparse checkout for the Gallery.

**Done when:**
- Every sampled PSU has an outcome row: retained, or a failure class; attempted and retained counts per stratum and source.
- Retained figures rerun from `bench/figures/` with the network blocked and produce the recorded engine object, 3 of 3 times on a 10-figure spot check.
- `bench/split.csv` and the manifest are committed in one freeze commit; its hash is recorded here.
- Capture on the development set: attempted, captured, refused (by reason), errored (by class), and leaves with count mismatches, per engine; compared with the predictions.

## Scope changes

_(append-only; never edit completed tasks above)_

- 2026-11-09 — **TidyTuesday is not in the v0 frame.** **Evidence:** the official repository's weekly directories (for example `data/2025/2025-01-14`) contain CSVs, `meta.yaml`, `readme.md` and images, and no plotting code; community code lives in personal repositories with no common index, so any list of them would be a convenience sample. **Effect:** the design's four sources become three; the post-cutoff subset, which TidyTuesday's dates would have served, will be drawn from dated Gallery posts and Bioconductor packages added after the model's cutoff. Needs the owner's review.
- 2026-11-09 — **Chart type is recorded, not stratified on.** **Evidence:** only the Gallery labels chart type (its `sectionLink`); package examples and vignettes have no label before running. **Effect:** strata are source plus two engine strata; chart-type distribution is reported.
