## What changed

Opened M6 as a continuation of the M5 feasibility slice. The plan is deliberately measurement-first: repair the pinned bench environment, validate masked scoring against a blinded open-world audit, extend the update/anchor ablation, measure SVG-only and prepared-visual conditions, and apply a cost gate before any repeated or two-model held-out extension. Engineering baselines remain under `bench/` and cannot become package dependencies.

No package code, held-out task labels, model prompts or model runs were changed in this planning step.

## Measured

- Host suite: `NOT_CRAN=true Rscript -e "devtools::test()"` → 22 files, 1644 passed, 0 failures and 0 skips, 296.7 seconds.
- Bench-container baseline from M4: 22 files, 186 tests, 1629 expectations, 0 failures, 0 errors and 5 explicit aisdk-dependent skips. The M5 material writer still cannot run in that image because `svglite` is absent.
- M5 deterministic fixture: 4/4 claim statuses matched, 20/20 correct masked bindings accepted, 20/20 wrong masked bindings rejected, 5/5 updates rebased and 16/16 prepared SVGs parsed with zero binding-answer leaks.
- M5 model evidence: 24 GLM development runs and 16 GLM held-out runs, one repeat. On the held-out tasks A, A + check and B were 4/4 correct with full coverage; B - check was 1/4. The first Gemini A run took 135.7 seconds and the remaining two-model matrix was stopped.
- Final host suite after the plan documents were committed: `NOT_CRAN=true Rscript -e "devtools::test()"` → 22 files, 1644 passed, 0 failures and 0 skips, 291.0 seconds.
- Not run in M6 opening: container parity, audit labels, model-based SVG-only or prepared-visual comparison, engineering baselines and the repeated/two-model extension.

## Surprises

- The M5 evidence is sufficient to plan the checking and environment work but not to support the main A-versus-B claim, its confidence interval, the visual effect or the cross-model result. → M6 Tasks 2–3 and Task 5.
- The pinned image lacks `svglite`, so host-generated M5 materials cannot yet be reproduced in the registered device-output environment. → M6 Task 1.
- A single Gemini sizing request used 135.7 seconds, so a two-model/five-repeat matrix cannot be assumed affordable. → M6 Task 3 cost gate.
- The masked metric and open-world audit have not been compared, and engineering baselines have no archived coverage. → M6 Tasks 2 and 4.

## What's next

Repair the pinned image and run the development/held-out material parity preflight before requesting any model run. Then freeze the audit sample and rubric, run the blinded audit and update ablation, and only after those checks register M6 predictions for the visual/D and cost-gated model extension.
