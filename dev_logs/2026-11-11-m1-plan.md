## Surprises

- **The names design §分类 calls cues are mostly not leaf names.** `geom_point`, `axis-l`, `strip-t` and the heatmap's `z_heatmap_body_1_1` are segments of the leaf's path or viewport; the leaf grob itself is often `GRID.text.n` or `GRID.rect.n` (196 of 342 leaves on the ggplot figures listed in full, 55 of 55 heatmap leaves). By element the share is small on ggplot (1280 of 24266: the large geom leaves are named) and nearly total on heatmaps and patchwork. The research rules already matched on path or viewport, so the 481 of 486 stands, but a rule set keyed by leaf name would not reproduce it. → plan Task 3 (rules read path and viewport segments); design §分类 note in Task 8.
- **On the bench, base legends can only be found from primitives.** Every base figure is a recorded plot, in which `legend()` leaves no entry of its own. → plan assumption 6 and Task 5.
- **The code cue the design proposes for base legends is order alignment.** §分类 matches `legend(`, `text(` calls to leaves "按出现顺序"; §元素归属 rejects order alignment for capture because it misassigns silently (the ggiraph example). The cue can still be used if the page checks it. → plan assumption 6 and Task 5; design note when Task 5 has measured it.
- **Appendix A writes rule output into the `structure` layer,** which needs the record core that M2 builds; M1 is listed before M2 in §实施计划. → plan open decisions 2 and 3; ADR-0007 in Task 6.
- **Two plans were still listed as active with only record-keeping left:** M0 (Task 9, done under bench v0) and bench v0 (Task 7, records).
