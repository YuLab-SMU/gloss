## Surprises

- **The names design §分类 calls cues are mostly not leaf names.** `geom_point`, `axis-l`, `strip-t` and the heatmap's `z_heatmap_body_1_1` are segments of the leaf's path or viewport; the leaf grob itself is often `GRID.text.n` or `GRID.rect.n` (196 of 342 leaves on the ggplot figures listed in full, 55 of 55 heatmap leaves). By element the share is small on ggplot (1280 of 24266: the large geom leaves are named) and nearly total on heatmaps and patchwork. The research rules already matched on path or viewport, so the 481 of 486 stands, but a rule set keyed by leaf name would not reproduce it. → plan Task 3 (rules read path and viewport segments); design §分类 note in Task 8.
- **On the bench, base legends can only be found from primitives.** Every base figure is a recorded plot, in which `legend()` leaves no entry of its own. → plan assumption 6 and Task 5.
- **The code cue the design proposes for base legends is order alignment.** §分类 matches `legend(`, `text(` calls to leaves "按出现顺序"; §元素归属 rejects order alignment for capture because it misassigns silently (the ggiraph example). The cue can still be used if the page checks it. → plan assumption 6 and Task 5; design note when Task 5 has measured it.
- **Appendix A writes rule output into the `structure` layer,** which needs the record core that M2 builds; M1 is listed before M2 in §实施计划. → plan open decisions 2 and 3; ADR-0007 in Task 6.
- **Two plans were still listed as active with only record-keeping left:** M0 (Task 9, done under bench v0) and bench v0 (Task 7, records). Of Task 7's four items, the design doc had no note on the frozen benchmark itself, although `bench/README.md` and the freeze log had the facts. → both plans closed this session with the owner's agreement; the note added to §评测设计.

- **Most checked bindings are ambiguous.** After the fixes, 15328 of 24378 checked ggplot elements lie within 0.5 pt of another row of their layer: an overplotted volcano plot (11173, exts-022) and a figure that maps a constant label in `aes()` over 1000 rows, so it draws the same label 1000 times per layer (4000, gallery-029; its rows differ only by row number). Position cannot say which row such an element drew. Design §绑定假设 says a passing back-substitution is Direct; that holds only when no other row passes. → plan scope change; design §绑定假设 dated note; whether colour, fill and size separate overlapping rows is open (candidate for the next slice).
- **The order assumption held; the binder's own pairing logic did not.** Run `1205`'s 2038 failures and 12275 unpaired elements came from three assumptions in the binder about ggplot's grob tree (one child per layer; children per group; outlines through `y`), not from rows drawn out of order. Each wrong pairing came out `failed`, none `verified`. → fixed in `c79312c`; plan Task 2 result.
- **Capturing a recorded grid page changed the caller's recording.** grid's display list restored by `replayPlot()` is the one inside the recording, and gloss wrapped it in place; a second capture of the same object failed. A user doing `gloss(rp)` twice would hit it. A copy through `serialize()` replays as two pages, so the fix uses a deep copy in memory. → `98ad505`, NEWS; development capture rerun unchanged.
- **Element-weighted shares are dominated by two figures.** exts-022 and exts-027 hold 17883 of 24783 ggplot layer elements in run `1231`; between runs `1205` and `1231` the share rose from 32.6% to 98.4%, and exts-022 alone (12254 elements checked in `1231`, 0 in `1205`) accounts for 49 of the 66 points. → `score-bind.R` prints per-figure shares beside the pooled share; nowhere else yet. The held-out report should give both.
