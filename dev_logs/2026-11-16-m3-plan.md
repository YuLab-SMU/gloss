## What changed

- Opened the M3 plan from the closed M2 record/anchor slice.
- Ordered the work by the riskiest unmeasured assumption: deterministic checks and claim eligibility, then R-side operations and overlays, then the HTML runtime, then ARIA/text/Web Annotation exporters.
- Kept M4 agent loops and M5 held-out evaluation out of the plan. The active plan records the browser runtime as a package capability; the existing `docs/index.html` storyboard is not counted as that runtime.

## Measured

- Host suite before opening the plan: `NOT_CRAN=true Rscript -e "devtools::test()"` → 18 files, 1506 passed, 0 failures, 0 skips; duration 277.1 s.
- Existing semantic evidence: `trend` on the mtcars built table has five of six group slopes negative and one automatic 4-cylinder slope `+3.067891`; the frozen offline proposal fixture has one each of `verified`, `failed`, `partial`, `refused` and `uncheckable`, with three cases resolved by owner audit.
- Existing M2 controlled update evidence: title 3/4, colour 4/4, data subset 2/4, add layer 4/4 and delete layer 4/4 automatic hits; missed targets were explicit invalid records.
- Repository inspection found `R/semantic-checks.R` and static `R/project-html.R`/`R/project-svg.R`, but no `inst/js/`, operation registration, `gl_apply()` or package-level ARIA/text/Web Annotation exporter.
- No code or test implementation was changed in this planning slice; no benchmark figure or held-out set was run.

## Surprises

- M3 is not a single missing function. The current package has a semantic check and a static bundle projection, while the shared operation vocabulary, runtime, overlay and accessibility/export contracts are absent. → plan scope: split M3 into six observable tasks instead of treating the milestone table as one implementation step.
- The design lists `exists` beside table-local checks, but the current `gl_check(table, ...)` boundary has no figure/anchor context. → Task 1 first measures whether it needs a separate figure-aware contract; no hidden context is added.
- The visual pilot and static documentation site already demonstrate semantic effects, but they do not exercise package projections or a browser runtime. → plan scope: require package-level fixtures and explicitly exclude the site from M3 runtime evidence.

## What's next

Start Task 1 with the closed check vocabulary and the frozen semantic proposal fixture. If `exists` requires a new context boundary, record the scope change before adding it; otherwise keep the check API table-only and proceed to explicit semantic layer schemas.
