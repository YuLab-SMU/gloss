### 当前定位

gloss 正在做一个 R 图形的可查询、可核验语义底座。输入是 R 图对象或绘图过程以及可取得的数据。让图在原来的绘图体系中画出来，保留设备给出的几何，再回答“这个形状来自哪个图层、哪一行数据”。未来由人或 agent 提议语义，代码检查后保存为记录，再用于交互、无障碍和图更新后的批注保留。

当前可运行的链条是：R 图 → 页面捕获与归属 → 数据表、坐标与绑定核验 → 查询 API → 图包保存和恢复。后面的提议入口、记录核心、交互和更新链条尚未打通。

工程底座已有实测；论文的两个主要主张——底座是否提升同一模型的表现、更新后记录是否仍挂对位置——尚无决定性实验。完整的用户工作流程也尚未形成。

### 路线如何收敛到这里

1. 捕获路线从“引擎转为 grob 后捕获”改成“让输入画出自己的页面再捕获”，避免截断坐标轴等自定义绘图流程被替换。grid 用组和探针记录归属；base 用显示列表回放。捕获与原页面比较，不能确认就拒绝或明确报告不确定。
2. 绑定由引擎提出元素与行的配对，通用代码将行放回页面与实际几何比较。比较按绘图原语和数量选择，避免每个 geom 都写一个处理器。当前配对主要到构建后的数据；回到用户原始数据行的血缘链未实现。
3. ADR-0009 停止继续为扩展包的特殊行为增添规则。已有三个例外冻结；以后由代码枚举、人或 agent 提议，再用相同的检查验证。
4. ADR-0007 将捕获时算出的绑定存进图和图包，`gl_bindings()` 已可查询。agent 路线开始验证恢复后的图能否支持提交时检查；agent 循环交给 aisdk，核心不依赖它。
